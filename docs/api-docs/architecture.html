Architecture Overview

Core Concepts › Architecture Overview

FlexTemplates 2.0 is a forkable Python framework: a Flet desktop UI, a FastAPI HTTP backend, and a SQLAlchemy data layer, all sharing one process. Every layer talks to its neighbours through standardized Pydantic contracts, so any piece can be swapped without touching the rest.

The LEGO Pitch

  • Plugs are Pydantic models — ActionRequest, ActionResult, Event.
  • Blocks are services with one job each — NavigationService, VaultService, ConnectionTester.
  • Builder is main.py — the only file that knows about concrete types.

Swap any block, the rest of the system can't tell. That's the architecture in one sentence.

The Layer Stack

main.py            ← wires everything (the only file that names concrete types)
  │
  ├── views/       ← Flet pages; receive services via props dict
  ├── api/routes/  ← FastAPI endpoints; receive services via Depends
  │
  ├── ui/          ← Flet building blocks (router, BaseView, components)
  │
  ├── services/    ← Business logic (NavigationService, VaultService, ...)
  ├── adapters/    ← Non-SQL backends (RedisAdapter, FileAdapter, BackendAdapter)
  │
  ├── auth/        ← JWT handler + RBAC dependencies
  ├── tasks/       ← APScheduler wrapper (TaskScheduler)
  │
  ├── repositories/← CRUD on ORM models
  ├── models/      ← SQLAlchemy ORM tables
  ├── database/    ← SessionFactory, ConnectionRegistry, UnitOfWork, migrations
  ├── security/    ← Vault (encrypted secrets store) + bcrypt helpers
  └── config/      ← AppConfig (pydantic-settings, reads .env)

How a Request Flows

Clicking a nav button

User clicks NavButton("Products", "/products")
  ↓
NavButton.on_click() fires
  ↓
nav_service.execute(ActionRequest(action="visit", data={"url": "/products"}))
  ↓
NavigationService updates history stack, publishes Event(type="nav.route_changed")
  ↓
EventBus dispatches to FletNavigationAdapter → page.go("/products")
  ↓
FletRouter.route_change(page):
  - lazy-loads lib.views.products
  - calls view(page, props) → ProductsView(page, props).render()
  ↓
ProductsView builds content, wrapped with appbar/sidebar by BaseView
  ↓
Router appends to page.views and calls page.update() → Flet repaints

NavigationService has no Flet import. FletNavigationAdapter is the one piece that does — swap it for a web adapter and nothing else changes.

The Core Pieces

Contracts — lib/contracts/base.py

Three Pydantic models, used everywhere:

class ActionRequest(BaseModel):
    action: str                      # "test", "visit", "set", "create"
    data: dict[str, Any] = {}

class ActionResult(BaseModel):
    success: bool
    data: dict[str, Any] = {}
    events: list[Event] = []
    error: str | None = None

class Event(BaseModel):
    type: str                        # "user.created", "nav.route_changed"
    payload: dict[str, Any] = {}

Services — lib/services/

Every service implements IService.execute(ActionRequest) → ActionResult. Most subclass SimpleService and get free dispatch + exception trapping:

class ConnectionTester(SimpleService):
    def test(self, data: dict) -> dict:
        factory = ConnectionRegistry.get(data["name"])
        # ... probe and return dict; SimpleService wraps it in ActionResult

Registries — ConnectionRegistry, CacheRegistry

Class-level singletons. main.py registers everything at startup:

ConnectionRegistry.get("postgres")     # returns a SessionFactory
CacheRegistry.get("redis")             # returns a RedisAdapter

All SQL databases use the DATABASE_<NAME> convention (DATABASE_POSTGRES → "postgres"). The PRIMARY_DATABASE env var names which registered DB the backend adapter targets (default "postgres").

BackendAdapter — lib/adapters/backend_adapter.py

The plug between Flet admin views and the backend. IBackendAdapter exposes four typed domain properties — views call these, never a URL:

PropertyInterfaceMethods
backend.authIAuthAdapterlogin(), logout(), current_user()
backend.usersIUserAdapterlist(), create(), delete()
backend.rolesIRoleAdapterlist(), create(), delete(), assign(), remove()
backend.schedulerISchedulerAdapterlist() — read-only job inspector

Two concrete implementations — swap in main.py, zero view changes:

# In-process (default):
backend = ServiceBackendAdapter(factory, user_service, scheduler)

# HTTP (local or remote):
backend = HttpBackendAdapter(base_url="http://localhost:8080")

/v1/ is the universal contract between the adapter layer and HTTP:

  • HttpBackendAdapter calls exactly these URLs (e.g. POST /v1/auth/login). It doesn’t know whether it’s talking to a local dev server or a remote host — it just calls /v1/… and trusts the contract.
  • ServiceBackendAdapter bypasses HTTP and calls Python methods directly — but the result is identical because both implement IBackendAdapter.
  • Any external client (JS dashboard, mobile app, CLI) can call the same /v1/ URLs. Write the endpoint once, consume from anywhere.
  • Side-by-side versioning: add /v2/ alongside /v1/ during a migration. Old clients keep working. No flag day.
  • The swap is transparent to views because views call backend.auth.login(), never a URL. The URL is an implementation detail of HttpBackendAdapter only.

Router & BaseView — lib/ui/

FletRouter turns URLs into views. Two routing modes:

  • Convention: /products → lib.views.products.view(page, props)
  • Named (for params): router.register("/products/{id}", "lib.views.product_detail")

BaseView is the page template — every view subclasses it and only writes build_content(). Admin views that require login subclass ProtectedView(BaseView) instead — redirect to /login is automatic if backend.auth.current_user() returns None.

class ProductsView(BaseView):           # public view
    title = "Products"
    show_sidebar = True
    def build_content(self):
        return ft.Column([ft.Text("Product list")])

class ManageUsersView(ProtectedView):   # auth-guarded view
    title = "Manage Users"
    def build_content(self):
        backend = self.props["backend"]

Vault — lib/security/

Encrypted secrets store with a two-key design (master + confirm). Vault starts locked — no auto-unlock at startup. The user unlocks via the /security view. After unlock, main.py wires vault-sourced DB and cache connections via the vault.unlocked event.

API Server — lib/api/

BackendServer runs Uvicorn in a daemon thread, sharing the same Python process and same ConnectionRegistry as the Flet UI. Routes auto-discover from lib/api/routes/.

Migrations — lib/database/migrations/

Alembic manages schema versioning. In dev, main.py runs alembic upgrade head automatically at startup. In production, run it in your deploy pipeline before starting the app:

DATABASE_URL=postgresql://user:pass@host/db alembic upgrade head

Testing

All 398 tests run on in-memory SQLite and a FakePage stand-in for ft.Page, so the suite has no external dependencies and finishes in ~10 seconds.

pytest tests/ -q              # run the full suite
pytest tests/ -k "backend"    # run only backend adapter tests

Async in Flet — the Short Version

Most event handlers are plain sync functions. When you need async (network probe, file I/O), use page.run_task(coro) — schedules a coroutine on Flet's event loop without blocking the UI. See lib/views/admin/databases.py for the full pattern.
